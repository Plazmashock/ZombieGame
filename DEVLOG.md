# LAST CHECKOUT — Development Log

## Tech decisions (Milestone 0)
| Decision | Choice | Why |
|---|---|---|
| Engine | Unity 6000.5.10f1 (Unity 6.5), project folder `ZombieGame` | Already installed; URP 17.5, Input System 1.20 (active), AI Navigation 2.0 already present |
| Render pipeline | URP (Universal 3D template) | Good-looking lighting (emergency lights, fog) while staying fast enough for big hordes. HDRP is too heavy for a solo beginner. |
| Input | Input System package (new) | Unity's current standard; old Input Manager is legacy. Controls are defined in code in one script (`PlayerInputReader`). |
| Player movement | Built-in `CharacterController` | Simple, predictable, no physics jitter |
| UI (for now) | OnGUI placeholder | Zero setup. Kept through Milestone 2 to stay fast; a proper Canvas UI comes in the polish milestone |
| Extra packages | None added | AI Navigation (NavMesh) is already in the project and will be used in Milestone 4 |

## Folder layout
```
Assets/_Project/
  Scripts/
    Player/        input, movement, mouse look
    Interaction/   IInteractable + PlayerInteractor (the "press E" system)
    World/         things in the level: doors, switches (later: barricades, loot containers)
    Items/         ItemDefinition (data) + WorldItem (pickups)
    Inventory/     PlayerInventory (the backpack)
    UI/            HUD
    Editor/        editor-only tools (scene builder) — not included in the game build
  Scenes/          Supermarket_Greybox.unity
  Materials/Greybox/
  Data/Items/       item ScriptableObjects (later: weapons, zombie types)
  (later) Prefabs/
```

## Architecture (simple on purpose)
- **PlayerInputReader** → the only script that reads keys. Everyone else asks it.
- **FirstPersonController** → moves the body. **PlayerLook** → turns the view.
- **PlayerInteractor** → ray from camera; anything implementing **IInteractable** can be used with E.
  Every future "usable" thing (loot, shelves to push, barricade spots, generators) plugs into this one contract.
- Planned: a **GameManager / PhaseManager** (Loot → Prepare → Defend → Recover) arriving in Milestone 2 with the timer.

## Milestone 3 — Game loop, armory, waves, new HUD  *(status: built 2026-11-09, waiting for playtest)*
Everything below sets itself up when you press Play (no menu clicks). Code lives in `Scripts/Game` and `Scripts/UI`.

Loop (`GameDirector`):
- LOOT 60 s → armory shutter slams at 0:00 → WAVE n → wave cleared → 4 s pause → LOOT again (store + armory restock)
- Last 10 s of loot: red warning lights + "GET OUT OF THE ARMORY". Still inside at 0:00 = sealed in = game over
- Waves grow: zombies = 4 + 2×wave, +15% health and +0.12 m/s per wave. Wave zombies always hunt you

Armory (`Armory`): built in code behind the back wall, door at the right end of the back corridor (x 10–11.6).
Racks: pistol / shotgun / rifle. Crates: 9mm ×24, 12 gauge ×12, 5.56 ×60. Zombies treat the closed shutter as a wall.

Weapons (`WeaponCatalog`, `PlayerShooting`): 2 = pistol, 3 = shotgun (8 pellets), 4 = rifle (full-auto, hold click).
Each gun keeps its own magazine. Shotgun/rifle models are built in code (`GunModelFactory`) from the pistol's materials.

Healing (`PlayerHealing`): H uses First Aid Kit (+60) or Painkillers (+25).

HUD (`GameHUD` + `UIKit`): uGUI canvas built in code, font Barlow Condensed (Resources/Fonts, OFL licence).
Phase timer, wave/kills, health with damage "ghost" bar, meds, pack weight, weapon + ammo + slot pills, dynamic crosshair,
hit/kill markers, interaction prompt, pickup feed, banners, damage vignette, backpack screen with Drop buttons, death screen.
The old OnGUI HUDs stay in the code as a fallback and switch themselves off while GameHUD runs.

Fixes this session:
- Zombies didn't die / guns showed nothing: `new MaterialPropertyBlock()` in a field initializer crashed every hit
- Muzzle flash filled the screen: it was being resized to 0.8–1.3 metres instead of ×0.8–1.3

## Milestone 3.1 — Zombie spawn fix, store makeover, armory start  *(status: built 2026-11-09, waiting for playtest)*
Bug fix — zombies never spawned / stood frozen:
- The Console said "Zombie N isn't close enough to walkable floor" for every zombie: the NavMesh was EMPTY.
- Cause: the store boxes are static-batched, so on Play Unity merges them into one mesh scripts can't read
  ("Combined Mesh ... does not allow read access"). The runtime bake read meshes, found nothing, built nothing.
- Fix (`NavMeshBaker.Bake`): bake from physics colliders instead. Player, loot and unlocked doors are ignored.
- `Zombie`: never gives up if the floor isn't there yet (retries twice a second); no more "Resume" errors.
- Zombies push unlocked doors open (`Door.All`). The emergency exit stays a locked wall.
- `WaveSpawner` warns in the Console if it can't find floor at any spawn spot.
- `LevelKit.Box(collider:false)` now switches the collider off immediately, so decorations don't end up in the NavMesh.

Store makeover (`StoreMakeover`, runs automatically on Play, built in code like the Armory):
- ~2000 products on aisle shelves, wall shelves and the pallet rack (some gaps = looted, some tipped over).
  Products never cover a real pickup item. Small decorations are merged into a few meshes per colour (fast).
- Colour-coded aisles: hanging number + department signs, header strips, price strips, end-cap displays (cover).
- SALE island with a can pyramid in the centre aisle (cover). Glowing fridges, fluorescent tube rows (some dead),
  2 flickering lights (`LightFlicker`). Checkout belts, card readers, candy racks, lane number signs.
- Checkerboard floor, green wall panelling, posters, EXIT sign, blood trail from storage, litter, shopping carts.
- Yellow floor line with arrows: entrance → centre aisle → back corridor → ARMORY (+ hanging ARMORY sign).
- Outside: "PRICEWELL MARKET" facade sign, sidewalk, bollards, zebra crossing, parking bays, 4 sodium street lamps,
  detailed old cars + 2 new wrecks (cover), cart corral, pallets. Dumpster moved so it no longer blocks the loading bay.

Player start: in the back corridor, 2.6 m in front of the armory shutter, facing it (`Armory.PlayerStartPoint`).
Any store zombie within 10 m of that spot is moved into the store at start.

## Milestone 5 — Bow pose, flashlight, zombie sounds, upgrade markers, roof ladder, supply truck  *(status: built 2026-11-10, waiting for playtest)*
1. Bow (`GunModelFactory.Poses`, `BowViewModel`): now held on the RIGHT of the screen (x 0.2). While drawing it eases a little towards the crosshair.
2. Flashlight (`Flashlight`): it used to sit 20 cm in front of the camera, next to the weapon. The weapon was blown out and its shadow blocked the beam.
   Now: beam starts at the camera, is much stronger (55, range 40) + a dim wide light for the edges; weapons are on their own

5. Roof access: the old stairs were built on the right side of the store, BEHIND the side fence — unreachable.
   Replaced by a ladder on the front wall (parking-lot side, x 18.6) — `World/Ladder` + climbing in `FirstPersonController`
